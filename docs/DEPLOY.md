# Deploying and running the website

The site is plain HTML, CSS and JavaScript, generated by `build.mjs` into `dist/`. One small server function, `functions/api/submit-deck.js`, handles deck submissions. Hosting is designed for Cloudflare Pages, because the live site already runs through Cloudflare.

## Run it locally

You need Node.js 20 or later. There are no packages to install.

```
npm run build     # writes dist/
npm test          # checks pages, links, translations and the form function
npm run preview   # serves dist/ at http://localhost:4321
```

The preview server also runs the deck form. Without real Brevo keys, it prints the emails it would send instead of sending them, and it skips the spam check.

## Set up Cloudflare Pages

1. In Cloudflare, go to **Workers & Pages → Create → Pages → Connect to Git**, and pick this repository.
2. Use these build settings:
   - **Framework preset:** None
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
   - **Root directory:** leave empty, so the `functions/` folder is found
   - **Environment variable:** `NODE_VERSION` = `22`
3. Add the settings from [`.env.example`](../.env.example) under **Settings → Variables and secrets**. Mark `BREVO_API_KEY` and `TURNSTILE_SECRET_KEY` as secrets.
4. Deploy. Every pull request gets its own preview address on `*.pages.dev`, so you can review changes before they go live.
5. When you're happy, go to **Custom domains** and add `www.01.capital` and `01.capital`. Cloudflare updates DNS for you because the domain is already on Cloudflare.

The old page addresses `index-CN.html` and `index-KR.html` redirect to `/zh/` and `/ko/` (see `dist/_redirects`).

## Set up Brevo

1. **Sender domain.** Go to **Senders, domains & dedicated IPs → Domains**, then add and authenticate `01.capital` by adding the DNS records Brevo shows (DKIM and DMARC). Without this, emails land in spam.
2. **Sender.** Add `noreply@01.capital`, or whatever you set as `BREVO_SENDER_EMAIL`.
3. **Deals inbox.** Create the mailbox set as `DEALS_INBOX_EMAIL` (proposed: `deals@01.capital`) with your email provider.
4. **List.** Go to **Contacts → Lists**, create a list such as "Deal flow", and put its ID in `BREVO_DEALFLOW_LIST_ID`.
5. **Contact attributes.** Under **Contacts → Settings → Contact attributes**, create these as **Text** attributes:
   `FULLNAME`, `COMPANY`, `WEBSITE`, `LOOKING_FOR`, `PILLAR`, `STAGE`, `RAISE_USD`, `COUNTRY`, `ONE_LINER`, `DECK_URL`, `SOURCE`, `LANGUAGE`.
6. **API key.** Go to **SMTP & API → API keys**, create a key, and save it as `BREVO_API_KEY`.

What happens on each submission:
- The founder is added to the list, or updated if they're already there, with their answers saved as attributes.
- The deals inbox gets an email with every answer. Reply to it to answer the founder directly.
- The founder gets a confirmation in the language they used on the site.

If saving the contact fails, for example because an attribute is missing, the deals email still goes out with a warning at the top.

## Set up Turnstile (spam protection)

1. In Cloudflare, go to **Turnstile → Add widget**, and add `01.capital`, `www.01.capital` and your `*.pages.dev` address as hostnames.
2. Put the **site key** (public) in `src/data/site.json` as `turnstileSiteKey`, then rebuild.
3. Put the **secret key** in Cloudflare Pages as `TURNSTILE_SECRET_KEY`.

The function rejects every submission if the secret key is missing, so the form can't be spammed by accident.

## Analytics

Turn on **Cloudflare Web Analytics** for the Pages project. It doesn't use cookies, which keeps the privacy policy simple.

## Editing content

| What | Where |
|---|---|
| Page text, in each language | `src/locales/en.json`, `zh-Hant.json`, `ko.json`, `ja.json` (same keys in every file) |
| Companies and logos | `portfolio.json`, plus logos in `src/assets/img/ecosystem/` |
| Team, fund facts, contact details, Turnstile site key | `src/data/site.json` |
| Articles | `src/content/articles/en/*.md`; put translations in `src/content/articles/<language>/` with the same file name |
| Privacy policy, terms, disclaimer | `src/content/legal/<language>/*.md` |
| Design | `src/assets/css/site.css` |

After any change, run `npm run build` and `npm test`, then commit both the change and the rebuilt `dist/` folder.
